Verdicts
--------
Case A (issue #6147 exact repro — client component omitted):
  FIXED. Dataset verify-a reached Bound; master+worker StatefulSets created and Running;
  the runtime ConfigMap was generated with master+worker sections and NO client section
  (treated as absent, not crashed on). Zero panics in the controller log. This is the
  outcome the issue asked for: "treat the client component as disabled and continue
  reconciling normally".

Case B (topology omitted entirely + DataLoad — round-1 finding F1's production path):
  FIXED. The choke-point validation in getRuntimeClass rejects the class at load time:
  "failed to get CacheRuntimeClass verify-b-empty: at least one component should be
  defined in runtimeClass verify-b-empty", surfaced as a Warning ErrorProcessRuntime
  event on the CacheRuntime; the DataLoad reports RuntimeNotReady instead of crashing
  the controller. Zero panics.

Note on the earlier phase-2 attempt: the first run used the binary WITHOUT the `start`
subcommand (it exited immediately), and the ACK addon manager auto-restored the deployed
pre-fix deployment from 0 to 1 replica; that restored pod briefly held the lease. The
capture above is from the corrected run, which held the lease for the full window
(lease holder at the end = the sandbox host running the patched binary).
